# Mobile ↔ Web Parity: Prioritized Implementation Plan

_Goal: bring the mobile app to feature parity with web across all 28 audited games. Web is the reference implementation; mobile should match it._

**Audit scope:** every game's mobile player view (`apps/mobile/components/games/*PlayerView.tsx`) read side-by-side against its full web implementation (`src/components/<game>/`, `src/components/host-lobby/`).

**Totals:** 353 gaps — 🔴 16 critical · 🟠 93 high · 🟡 137 medium · ⚪ 107 low.

- 🔴 **Critical** = the game cannot be fully played on mobile (broken/unplayable).
- 🟠 **High** = a core feature players will immediately notice missing.
- 🟡🟠 **Medium / Low** = settings and polish.

**How to read this plan:** work top-down by phase. P0 makes broken games playable. P1 builds shared mobile primitives *once* that close gaps across 10+ games at a time — do this before grinding P2 per-game, or you'll reimplement timers/spectator/results 15 times. P2/P3 are the long tail. The full per-game gap list is the Appendix at the bottom.

## Phase 0 — Ship-blockers: unplayable / broken games

These games are either impossible to complete on mobile or play fundamentally wrong. Each needs new mobile `game-api.ts` wrappers + UI. Highest ROI.

### P0.1 — Monopoly economy & trading  🔴🔴🔴🔴🔴🔴
The single biggest lift. Mobile has **no** build/mortgage/trade layer at all — a player can't develop property, can't raise cash when in debt (forced to forfeit), and can't trade.
- Add `postMonopolyBuild`, `postMonopolyMortgage`, `postMonopolyTrade` wrappers in `apps/mobile/lib/game-api.ts` (web hits `/api/monopoly/build|mortgage|trade`).
- Build & trade panel: **+House / +Hotel / Sell house / Sell hotel** (needs full-color-set detection), **Mortgage / Unmortgage**.
- Full **trade builder** (offer/request cash + properties + jail cards, review + confirm) and **incoming-trade accept/decline modal**.
- Player-facing **your-properties list** + **color-set completion tracker** (prerequisite UI for building).
- Port from `src/components/monopoly/MonopolyGamePanels.tsx` (`MonopolyManagePanel`, `renderPropertyCard`) and `MonopolyTurnModals`.

### P0.2 — Missing mobile host views  🔴🔴
Two games have **no host view on mobile** at all — the host falls through to the player composer.
- **Secret Message:** host must see the **inbox** of received messages, not the sender box (currently unplayable as host). Port `SecretMessageHostView`; register a mobile host view.
- **Anonymous Messages:** port `AnonymousMessagesHostView` (start session, watch feed, remove/mute, end session). Register in the mobile host registry.

### P0.3 — Poll family core logic  🔴 + gender subsystem 🟠
- **Pick a Number:** implement the turn-based picker flow (only `submitter_player_id` picks; others see "waiting"; reveal + answer-out-loud). Mobile currently lets everyone pick simultaneously — the game doesn't work as designed.
- **Gender-based voting** (SMK / Red-flag-Green-flag / Parent Approval): add gender selection at join + per-round gender gating. Entire subsystem absent on mobile.

### P0.4 — Other broken mechanics  🔴 each
- **Matching Pairs:** add the **memorize phase** (cards revealed at round start) — without it the game is blind luck, not memory. Also fix **multi-round scoring** (mobile miscounts / has no round-results screen).
- **Sudoku:** add **live standings** + **opponent cell-ownership colors** — currently reduces to solo Sudoku with no race.
- **Mahjong:** enable **self-draw win (tsumo)** on your own turn (mobile's Mahjong button is gated behind `!isMyTurn`) + concealed/added kong.
- **Word Hunt:** add the **countdown timer + time-up enforcement** (round never ends on mobile).
- **Snake & Ladder:** render the **actual board** (currently a plain text list — no board, snakes, ladders, or tokens).
- **NPAT / I Call On:** add the **live scoreboard** (players never see anyone's answers or marks).

## Phase 1 — Shared infrastructure (build once → fixes many games)

These gaps repeat across 10+ games. Build reusable mobile components and wire them everywhere, rather than per-game.

### P1.1 — Turn / countdown timer primitive  🟠 (~10 games)
A mobile turn-timer component (countdown, urgent state, client-side `expire-turn` call). Missing in Snake & Ladder, Tic Tac Toe, Ludo, Yahtzee, Sudoku, Scrabble (chess-clock + game-length), NPAT, Two Truths, Anonymous Messages, Matching Pairs. Hosts can already *set* timers; mobile just never shows them.

### P1.2 — Spectator / viewer + "you're out, watch" states  🟠 (~8 games)
A shared read-only/watch surface + `computeScreen` "watching" state. Missing across Whot, Crazy Eights, Bingo, Word Hunt, Quiplash, Sudoku, Monopoly. Also the "you emptied your hand → watch till end" state for card games.

### P1.3 — Rich finish / results screens  🟠 (~9 games)
Replace the generic `GameFinishPanel` with web-parity finish surfaces: winner hero, share-as-image card, per-player breakdowns, community post. Missing in Codewords (MVP cards, board reveal), Word Hunt (words review, reveal-all), Quiplash, Mahjong (yaku/fan/fu breakdown), NPAT, Word Rush, poll family (per-gender leaderboards, all-rounds recap). Several need new builders in `apps/mobile/lib/finish-leaderboards.ts`.

### P1.4 — Replay / play-again ready-up  🟠
Handle `game.replay_pending` + `ReplayReadyRing` on mobile so players can join the "play again · same settings" loop (Quiplash and others simply ignore it today).

### P1.5 — Individual-mode guess masking (anti-cheat)  🟠
In individual mode, hide other players' guess **text** (show "guessing…" / "guessed ✅"). Mobile leaks answers in **Quick Draw** and **Describe It**, letting players copy correct answers.

### P1.6 — Apply host-chosen appearance in gameplay  🟠
Host picks are written but ignored by the mobile renderer:
- **Chess:** apply `chess_board_theme` / `chess_piece_set` (mobile hardcodes the board + Unicode glyphs) + add the per-player "Board & pieces" picker.
- **Monopoly:** apply `game.theme` editions (themed money, palette, space names, Arctic snowfall).

137 🟡 + 107 ⚪ items: status banners, progress bars, contextual hints, sound/animation, and minor settings. Batch these by category (e.g. "add all missing countdown bars," "add all in-game standings strips") once P1 primitives exist. Full list in the Appendix.

## Suggested sequencing

1. **Sprint 1 — P0.2 + P0.3 + P0.4** (missing host views, poll logic, the six other broken mechanics). Mostly self-contained; makes every game at least *completable*.
2. **Sprint 2 — P0.1 Monopoly** (large, isolated).
3. **Sprint 3 — P1.1 + P1.2** (timer + spectator primitives) applied across all games.
4. **Sprint 4 — P1.3 + P1.4 + P1.5 + P1.6** (results, replay, anti-cheat, appearance).
5. **Ongoing — P2 then P3**, game by game.

**Working notes:** most web logic already lives in `src/components/<game>/` and `src/lib/` — port the logic, add the mobile `game-api.ts` wrapper for any new endpoint, and reuse `finish-leaderboards.ts` builders. The API routes already exist server-side for nearly everything mobile is missing (build/mortgage/trade/resign/expire-turn), so most of this is **client UI + API wrappers**, not backend work.

# Appendix — Full per-game gap list

Ordered by severity weight. 🔴 critical · 🟠 high · 🟡 medium · ⚪ low.

### Monopoly — _partial_  (🔴6 🟠5 🟡5 ⚪3)

> Mobile Monopoly can be joined and can play the roll/buy/pay-rent/jail/auction/settle-debt loop, but it is missing the entire "Build & trade" half of the game. The whole MonopolyManagePanel — build houses/hotels, sell buildings, mortgage/unmortgage, the full player-to-player trade builder, and the incoming-trade accept/decline modal — does not exist on mobile, and the corresponding API functions (postMonopolyBuild, postMonopolyMortgage, postMonopolyTrade) are not even defined in the mobile game-api layer. This is critical: a mobile player can never develop property or trade, and a cash-poor player in the raise_funds phase can only Pay or Forfeit (no mortgaging or selling), forcing avoidable bankruptcy, and cannot respond to a trade a web player sends them. On top of that, the host-selected Edition/theme is completely ignored by the mobile board (hardcoded colors, plain money, default names, no snowfall), there is no spectator/viewer mode, no color-set portfolio or owned-property view, and the finished screen lacks the shareable results card and community-post action. The lobby settings sheet does support choosing max players, turn timer, game length, and edition, so pre-game parity is decent — but in-game parity is only partial and the missing property/trade mechanics make the game not fully playable on mobile.

- 🔴 **Build houses (+House)** _(gameplay)_ — Web's Build & trade panel lets a player who owns a full color set add houses to any property, showing the cost. Mobile has NO build panel and no postMonopolyBuild API function at all — a player can never develop property, so half the core Monopoly economy (rent escalation via houses) is unreachable on mobile. `web: MonopolyGamePanels.tsx renderPropertyCard (~line 707) — postAction('/api/monopoly/build', {action:'buy_house'})`
- 🔴 **Build hotels (+Hotel)** _(gameplay)_ — Web upgrades 4 houses to a hotel via the '+ Hotel' button. Completely absent on mobile — no button, no API call. `web: MonopolyGamePanels.tsx renderPropertyCard (~line 717) — build action 'buy_hotel'`
- 🔴 **Sell house / Sell hotel** _(gameplay)_ — Web lets players sell buildings back to the bank to raise cash. Missing on mobile. Combined with missing mortgage, a mobile player in debt with lots of buildings cannot liquidate them — they are forced to forfeit. `web: MonopolyGamePanels.tsx renderPropertyCard (~lines 727-746) — build actions 'sell_house'/'sell_hotel'`
- 🔴 **Mortgage property** _(gameplay)_ — Web lets any property owner mortgage a property for cash. Mobile has no mortgage UI and no postMonopolyMortgage function. In the raise_funds phase mobile only offers 'Pay debt' or 'Forfeit', so a player who lacks cash but owns property is forced to go bankrupt instead of mortgaging — a broken/unfair debt flow versus web. `web: MonopolyGamePanels.tsx renderPropertyCard (~line 751) — postAction('/api/monopoly/mortgage', {action:'mortgage'})`
- 🔴 **Propose a trade (cash/properties/Get-Out-of-Jail cards)** _(gameplay)_ — Web has a full trade builder: pick a target player, offer/request cash, tick your & their properties, include jail cards, one-way-gift confirmation, a review step and confirm dialog, and cancel-offer. Mobile has zero trading UI and no postMonopolyTrade function — player-to-player trading, a core Monopoly mechanic, is entirely impossible on mobile. `web: MonopolyGamePanels.tsx MonopolyManagePanel tradeSection (~lines 379-667)`
- 🔴 **Accept / decline an incoming trade offer** _(gameplay)_ — Web pops a modal for the recipient reviewing every item with Accept/Decline buttons, plus an inline 'Trade offer waiting' nudge. Mobile has no trade modal or accept/decline path, so even if a web player sent a trade, a mobile recipient literally cannot respond to it. `web: MonopolyGamePanels.tsx MonopolyTurnModals (~lines 191-267) + MonopolyActiveLayout incomingTrade banner`
- 🟠 **Unmortgage property** _(gameplay)_ — Web lets owners pay to lift a mortgage and restore rent collection. Absent on mobile; a mortgaged property can never be reinstated. `web: MonopolyGamePanels.tsx renderPropertyCard (~line 759) — mortgage action 'unmortgage'`
- 🟠 **Color-group portfolio / set-completion tracker** _(gameplay)_ — Web groups your properties by color, shows a checkmark and progress dots when you complete a set (the prerequisite to building). Mobile only lists each player's cash and current space — there is no per-property ownership view or set-completion indicator for the player. `web: MonopolyColorPortfolio + MonopolyColorSetDots in MonopolyGamePanels.tsx (~lines 671-819)`
- 🟠 **Your-properties management list** _(gameplay)_ — Web shows each owned property as a card with color bar, current rent, building level (houses/hotel), mortgaged state, and per-property action buttons. Mobile gives the player no list of the properties they own and no per-property detail at all. `web: MonopolyGamePanels.tsx MonopolyManagePanel 'Your properties' section (~lines 783-828)`
- 🟠 **Edition/theme rendering in gameplay (themed money, board palette, space names, Arctic snowfall)** _(customization)_ — The host can pick a Monopoly Edition in the lobby on both platforms, but the mobile board/player view ignores game.theme entirely — it renders a hardcoded green/beige board, formats money with plain formatMonopolyMoney, uses default space names, and has no themed palette or Arctic snowfall. On web every edition retitles spaces, restyles money and the board, and adds ambient effects. Mobile players see the default edition regardless of the host's choice. `web: monopoly-themes.ts (formatThemedMoney/themedSpaceName/getBoardPalette) used throughout; ArcticSnowfallOverlay in MonopolyActiveLayout.tsx`
- 🟠 **Spectator / viewer mode (watch an in-progress game live)** _(lobby)_ — Web lets someone open an already-active game and join as a read-only viewer (spectator board layout, ViewerModeBanner, 'Watching live'). Mobile's computeScreen always routes a player-less user to the normal join-as-player flow; there is no viewer join, so late arrivals cannot spectate on mobile. `web: MonopolyPlayerView.tsx joiningAsViewer path + ViewerModeBanner + spectator layout in MonopolyActiveLayout.tsx`
- 🟡 **Get-Out-of-Jail card inventory display** _(gameplay)_ — Web shows how many Get Out of Jail Free cards you hold in your inventory (and lets you trade them). Mobile only surfaces the card as a 'Use get-out-of-jail card' button while in jail; there is no inventory readout otherwise and cards can't be traded. `web: MonopolyChrome MonopolyJailCardInventory, used in MonopolyManagePanel & MonopolyBoardCenter`
- 🟡 **Personalized status banners (cash/rent/trade event messages)** _(ui-polish)_ — Web builds player-specific banner messages (e.g. 'You paid X rent to Y', trade accepted/declined) with themed text. Mobile just renders the raw board.status_message string with no personalization or trade/cash/rent event formatting. `web: MonopolyActiveLayout.tsx (~lines 84-114) formatCashMessageForPlayer/formatRentMessageForPlayer/formatTradeMessageForPlayer + MonopolyStatusBanner`
- 🟡 **Client-side turn/action auto-advance on deadline** _(gameplay)_ — Web auto-submits the default action when a per-action deadline expires (auto-roll, auto-pay rent, auto-pass auction, auto-auction on buy, auto-forfeit on raise-funds). Mobile shows a countdown badge but never auto-acts, so a stalled mobile player relies entirely on server-side timeout handling for these phases. `web: MonopolyBoardCenter.tsx useMonopolyDeadlineTimer auto callbacks (~lines 149-175)`
- 🟡 **Post win to community** _(social)_ — On web the winner gets a 'Post win to community' action on the finished screen. Mobile's GameFinishPanel has no community-post entry point for the Monopoly winner. `web: MonopolyPlayerView.tsx finished screen — PostWinToCommunity (~line 446)`
- 🟡 **Share results card (image capture) with net-worth breakdown** _(results)_ — Web renders a rich, screenshot-shareable final results card (winner hero, medal ranks, per-player property count, cash and total net worth, share button). Mobile shows a generic GameFinishPanel leaderboard (net worth + property/cash detail text) with no shareable capture card or winner hero styling. `web: MonopolyFinalResultsShareBlock.tsx — ShareResults capture + FinishedWinnerHero + per-player net worth/property breakdown`
- ⚪ **In-flow nudge banners to the Build & trade panel** _(ui-polish)_ — Web shows contextual prompts pointing the player to the build/trade panel and a badge counting available build actions. N/A on mobile only because the entire panel they point to doesn't exist. `web: MonopolyActiveLayout.tsx (~lines 202-233) — 'Trade offer waiting', 'You can build', 'Raise cash — mortgage or sell'`
- ⚪ **Turn strip / current-space / cash chrome header** _(ui-polish)_ — Web has a dedicated header row: whose turn + phase + timer, the space you're on with owner/rent, and a cash badge. Mobile approximates this with a plain TurnBanner and a per-player scores list, losing the current-space owner/rent detail and dedicated cash badge. `web: MonopolyChrome MonopolyTurnStrip / MonopolyCurrentSpace / MonopolyCashBadge in MonopolyActiveLayout.tsx (~lines 160-200)`
- ⚪ **Game rules link in lobby/waiting** _(ui-polish)_ — Web surfaces a 'how to play' rules link on the waiting screen. Not present in the mobile waiting/lobby view. `web: MonopolyPlayerView.tsx waiting screen — GameRulesLink (~line 367)`

### Sudoku — _partial_  (🔴2 🟠4 🟡8 ⚪5)

> Mobile Sudoku implements only the bare solo-solving loop: render the puzzle, tap a cell, tap a digit to submit, and see your own solved cells turn green with a one-line result message. Every layer that makes it a competitive multiplayer race is absent on mobile. There is no live standings list (web shows each opponent's rank, completion %, time, points, and a MiniGrid of their solved cells), no per-player cell-ownership coloring on the board (opponents' progress is invisible), no countdown timer bar (even though the host can set a time limit), no personal status header with rank/completion, and no time tracking anywhere. Solving aids and controls are also missing: undo, erase, same-number highlight, completed-number checkmarks on the pad, wrong-answer red marks, completion %, and the correct/flash animations. Whole sub-flows are gone too: viewer/spectator mode with a watch-player switcher, the late-join player-vs-viewer choice, localStorage draft persistence, the replay ready-up ring, and the finish-screen community share. The host lobby settings (max players, max time, theme, late-join) DO reach parity via HostLobbySettingsSheet, so the gap is entirely in the player/in-game experience, which is currently critical-level incomplete for multiplayer.

- 🔴 **Live in-game player standings / leaderboard** _(gameplay)_ — Web renders a live standings list under the board: each opponent's rank, completion %, time spent, points, and a MiniGrid thumbnail of the cells they've solved. This is the entire competitive feedback loop of the multiplayer race. Mobile renders ONLY the board, number pad, and a one-line result message — during play you have zero visibility into opponents or your own standing. The game reduces to solo Sudoku on mobile. `web: SudokuPlayerView.tsx lines 891-929 (leaderboard.map with MiniGrid, rank, completion %, time, points)`
- 🔴 **Opponent cell-ownership colors on the board** _(gameplay)_ — Web colors each solved cell by which player first claimed it (per-player colors), so you can see rivals filling the grid in real time and which cells are already taken. Mobile only styles your own solved cells green (cellSolved) and gives cells gray — it never passes cellOwners/playerColors, so opponents' progress is invisible and there is no race tension. `web: SudokuBoard.tsx getCellDisplayColor + cellOwners/playerColors (lines 89-121); SudokuPlayerView builds cellOwners/playerColors (368-385)`
- 🟠 **Puzzle countdown timer bar** _(gameplay)_ — Web shows a 'Puzzle time left' countdown bar with progress fill and an urgent (red) state under 60s, driven by the host's max-time-limit setting. Mobile host CAN set the duration (DurationGamesSection) but the mobile player view renders no timer at all — players have no idea how much time remains before scores are locked. `web: SudokuGameTimerBar.tsx + SudokuPlayerView.tsx line 755`
- 🟠 **Per-player time-spent display** _(gameplay)_ — Web shows an elapsed ⏱️ time for you in the status header and for every player in standings and the final leaderboard (tie-break / bragging metric). Mobile shows no time anywhere in-game and omits time from the finish standings. `web: SudokuPlayerView.tsx getPlayerTimeSpent used in header (811-818), watched header, standings (897-921), and finish leaderboard (713-723)`
- 🟠 **Player status header (color chip, rank, completion %)** _(ui-polish)_ — Web shows a header with your color swatch, name, live rank (e.g. '2nd'), and your completion percentage. Mobile has no status header — you can't see your rank or progress % while playing. `web: SudokuPlayerView.tsx lines 800-819`
- 🟠 **Spectator / viewer mode (watch a player's board)** _(social)_ — Web supports viewers: a ViewerModeBanner, a horizontal player-picker to switch whose board you watch (read-only rendering of that player's grid + their rank/time/completion), and a promote-to-player flow. Mobile's Screen type has no viewer path — everyone is a player and there is no way to watch or spectate. `web: SudokuPlayerView.tsx lines 756-865 (isViewer branch, watched-player switcher, ViewerModeBanner, promote-to-player)`
- 🟡 **Late-join choice screen (join as player vs viewer mid-game)** _(lobby)_ — Web presents a late-join choice (join as player or as viewer) with context when opening the link after the puzzle has started. Mobile's computeScreen only returns join/waiting/playing/finished — no late_join_choice; a late arrival just gets the plain join screen. `web: SudokuPlayerView.tsx lines 629-645 (LateJoinChoice) + computeScreen 'late_join_choice'`
- 🟡 **Undo button** _(gameplay)_ — Web has an Undo control backed by an undo stack that reverts your last local cell entry/erase. Mobile has no undo button and no undo stack. `web: SudokuBoard.tsx toolbar (lines 201-205) + SudokuPlayerView handleUndo (562-581), undoStack`
- 🟡 **Erase button** _(gameplay)_ — Web has an Erase control to clear a selected local draft cell. Mobile has no erase key on the number pad and no clear action; the mobile `drafts` state is initialized but never mutated (dead). `web: SudokuBoard.tsx toolbar (lines 207-209) + SudokuPlayerView handleErase (549-560)`
- 🟡 **Wrong-answer red cell display** _(gameplay)_ — On a wrong submission web writes the wrong number into the cell in red (wrongDrafts) so you see your mistake in place. Mobile only prints 'Wrong — try again' as a text line and leaves the cell blank — no visual mark of the incorrect guess. `web: SudokuBoard.tsx draftWrongCells rendering (lines 101, 165) + SudokuPlayerView wrongDrafts state`
- 🟡 **Same-number highlight on tap** _(gameplay)_ — Web: tapping a filled/given cell highlights every cell containing that same number (light-blue) — a standard Sudoku solving aid. Mobile has no highlight; tapping a given/solved cell is a no-op. `web: SudokuBoard.tsx highlightNumber (lines 105-118) + SudokuPlayerView handleCellSelect (436-455)`
- 🟡 **Completed-number checkmarks on number pad** _(ui-polish)_ — Web marks a number pad key with a green ✓ once all nine instances of that digit are solved, so you know which digits are done. Mobile's pad is a plain 1-9 with no completed-state styling. `web: SudokuBoard.tsx number pad (lines 214-239, completedNumbers) + SudokuPlayerView completedNumbers (394-397)`
- 🟡 **Post-win share to community** _(results)_ — On the web finish screen the winner gets a PostWinToCommunity card to share their win. Mobile's GameFinishPanel has no community-share option. `web: SudokuPlayerView.tsx finished view PostWinToCommunity (731-738)`
- 🟡 **'Play again · same settings' replay ready-up ring** _(lobby)_ — Web reopens the lobby with a ReplayReadyRing (ready = holding a seat, min-players gate) when the host chooses 'Play again · same settings'. Mobile's waiting screen uses the generic LobbyView with no replay-ready ring path shown for the replay_pending state. `web: SudokuPlayerView.tsx waiting view replay_pending branch with ReplayReadyRing (648-665)`
- ⚪ **Board completion % star indicator** _(ui-polish)_ — Web toolbar shows overall board completion percentage with a star icon. Mobile has no completion indicator on/near the board. `web: SudokuBoard.tsx toolbar ToolbarButton with StarIcon (lines 197-200)`
- ⚪ **Correct-placement pulse and unit-completion flash animations** _(ui-polish)_ — Web animates a scale pulse across matching numbers on a correct placement and a brief amber flash across any row/column/box you just completed. Mobile has no feedback animations. `web: SudokuBoard.tsx correctPulse + flashUnits (lines 103-104, 113-121, 187-193); SudokuPlayerView triggerUnitFlash/getNewlyCompletedUnits (120-128, 505)`
- ⚪ **Toast feedback with awarded points** _(ui-polish)_ — Web shows a floating green/red toast ('✓ Correct! +N pts' / '✗ Wrong! -N pts'). Mobile shows a static '+N pts' / 'Wrong — try again' text line with no penalty amount and no styled toast. `web: SudokuPlayerView.tsx showToast + submitCell (115-118, 501-523)`
- ⚪ **Local draft persistence across reload (localStorage)** _(gameplay)_ — Web persists the working grid to localStorage keyed by round+player, restoring it on reload. Mobile keeps no local grid persistence. `web: SudokuPlayerView.tsx loadSavedGrid/saveGrid (50-78, 185-186)`
- ⚪ **Final leaderboard time + paginated standings** _(results)_ — Web finish leaderboard appends each player's elapsed time (⏱️) to their row and uses PaginatedLeaderboard. Mobile's finish uses a plain pointsLeaderboard with no time column. `web: SudokuPlayerView.tsx PaginatedLeaderboard with per-row time (709-730)`

### Poll family (Smash/Marry/Kill, Would You Rather, etc.) — _partial_  (🔴1 🟠7 🟡4 ⚪4)
